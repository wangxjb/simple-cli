# Agent 能力路线图

这份路线图用于拆解 `simple-cli` 后续要补齐的 agent 能力。每完成一个能力，都需要新增或更新对应能力文档。

## 已完成能力

### 终端交互界面

- 原因：用户需要在命令行窗口内持续对话，而不是每次运行一次脚本。
- 解决问题：提供全屏交互、输入栏、历史消息、滚动查看。
- 当前实现：基于 `blessed` 构建 TUI，入口命令为 `scli`。
- 后续改进：提升布局稳定性和渲染性能。

### 模型驱动循环

- 原因：agent 应该由模型决定下一步，而不是 CLI 写死业务判断。
- 解决问题：支持“用户输入 -> 模型返回工具调用 -> CLI 执行 -> 结果回传 -> 最终回答”的循环。
- 当前实现：`src/agent-loop.js` 负责循环控制。
- 后续改进：抽象更严格的轮次状态和终止条件。

### 本地只读工具

- 原因：模型需要读取项目上下文才能回答本地代码问题。
- 解决问题：支持列文件、读文件、搜文本。
- 当前实现：`src/tools.js` 提供 `list_files`、`read_file`、`search_text`。
- 后续改进：补充 git 状态、diff、测试执行等工具。

### 模型过程展示

- 原因：调试 agent 时需要看到每轮模型输入、输出和工具结果。
- 解决问题：让用户理解 agent 为什么这么做，便于排查模型协议问题。
- 当前实现：UI 展示发送给模型的信息、模型思考过程、原始输出、工具调用和结果。
- 后续改进：增加日志文件和会话导出。

### 安装入口

- 原因：用户希望从 GitHub 下载后，通过短命令进入交互窗口。
- 解决问题：提供 `scli` 命令入口。
- 当前实现：`package.json` 的 `bin.scli` 指向 `src/cli.js`。
- 后续改进：发布到 npm，降低安装成本。

## 待实现能力

### 001 工具协议层

- 原因：当前工具调用依赖模型输出 JSON 文本，容错和校验还不够强。
- 解决问题：规范工具调用格式、参数校验、错误提示和自动纠错。
- 实现方向：定义工具 schema，统一校验入口，返回结构化错误。
- 验证方式：覆盖非法 JSON、未知工具、缺失参数、参数越界等测试。

### 002 工具权限系统

- 原因：后续会加入 shell、文件编辑等能力，必须先有权限边界。
- 解决问题：区分只读、可写、危险操作，避免 agent 误执行破坏性命令。
- 实现方向：给工具定义风险等级，执行前按等级决定是否需要用户确认。
- 验证方式：只读工具自动执行，写操作需要确认，危险操作直接拒绝。

### 003 工具系统扩展

- 原因：只靠读文件和搜索不足以完成真实代码任务。
- 解决问题：让 agent 能理解 git 状态、运行测试、查看 diff。
- 实现方向：新增 `git_status`、`git_diff`、`run_command`、`run_test` 等工具。
- 验证方式：用真实项目任务跑端到端验证。

### 004 上下文管理

- 原因：长会话会持续增长，最终超出模型上下文或引入噪声。
- 解决问题：控制 token 成本，保留关键上下文。
- 实现方向：增加历史摘要、工具结果摘要、消息裁剪和上下文预算。
- 验证方式：模拟长会话，验证不会无限发送历史消息。

### 005 文件编辑能力

- 原因：真正的 coding agent 需要能修改代码，而不只是回答问题。
- 解决问题：支持模型提出修改，CLI 应用补丁，并展示 diff。
- 实现方向：引入 patch 工具，先限制在工作区内，写入前展示变更。
- 验证方式：新增小型代码修改任务，检查文件变化和测试结果。

### 006 任务规划能力

- 原因：复杂任务需要拆解步骤，否则模型容易一次性输出混乱方案。
- 解决问题：让 agent 有计划、有进度、有状态。
- 实现方向：加入 plan/todo 状态，执行中逐步更新。
- 验证方式：用多步骤任务验证计划更新是否准确。

### 007 验证闭环

- 原因：agent 修改代码后必须验证，不能只停留在“看起来完成”。
- 解决问题：把测试、失败信息和修复循环纳入主流程。
- 实现方向：工具执行测试，失败结果回传模型，模型继续修复。
- 验证方式：构造失败测试，验证 agent 能修到通过。

### 008 模型适配层

- 原因：项目不应该被 DeepSeek 绑定死。
- 解决问题：支持替换 OpenAI、DeepSeek 或兼容 OpenAI API 的模型。
- 实现方向：抽象 `ModelProvider`，保留 DeepSeek provider 作为默认实现。
- 验证方式：用 mock provider 覆盖统一接口，用 DeepSeek 跑真实联调。

### 009 会话记录与回放

- 原因：agent 行为复杂时，需要可复盘的 trace。
- 解决问题：保存每轮模型输入、输出、工具调用和工具结果。
- 实现方向：增加本地日志目录和会话 ID，支持导出 markdown/json。
- 验证方式：跑一次任务后，能从日志重建完整过程。

### 010 发布体验

- 原因：GitHub clone + npm link 仍然有门槛。
- 解决问题：让用户像安装普通 CLI 一样安装和升级。
- 实现方向：整理 npm 包信息、版本策略、发布脚本和安装文档。
- 验证方式：本地 npm pack 安装验证，后续再发布 npm。

## 实施顺序

建议先做 `001 工具协议层`，再做 `002 工具权限系统`。这两个能力是后续执行命令、编辑文件、运行测试的基础。
